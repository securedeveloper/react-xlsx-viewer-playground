# react-xlsx-viewer playground

Interactive playground for [react-xlsx-viewer](https://www.npmjs.com/package/react-xlsx-viewer), the read-only spreadsheet viewer for React built on [javascript-excel](https://github.com/securedeveloper/javascript-excel). Open a sample or your own `.xlsx`/`.csv`, try every prop, and copy the code that reproduces what you see.

Everything runs in the browser. Files you open are read locally and never uploaded; there is no backend, tracking or cookies.

## What it shows

- **Samples:** javascript-excel's conformance corpus (values, text, dates, formulas, fonts, fills, borders, alignment, number formats, colours, widths, merges and views, hyperlinks, builders, and a kitchen sink). Each sheet says what it tests and what Excel shows.
- **Your own file:** drag and drop, or choose an `.xlsx`, `.xlsm`, `.xltx`, `.xltm`, `.csv` or `.tsv`.
- **Props:** zoom, chrome theme and accent (the `--xv-*` custom properties), `locale`, `labels` (presets or your own JSON), `showGridLines`, `showHeaders`, `showFormulaBar`, `showSheetTabs`, `showStatusBar`, `showHiddenSheets`, `worker`, and the height.
- **Examples:** one click loads a scenario (frozen panes and RTL, hidden sheets, German number formats, a translated UI, minimal chrome, a custom theme, links, a worker read, two million cells).
- **Selection and events:** the current selection, `ref.copy()`, `ref.scrollTo()`, `ref.focus()`, and a log of `onLoad`, `onSheetChange`, `onZoomChange`, `onHyperlink`, `onWarning` and `onError`.
- **Large sheets:** a workbook of up to 200,000 × 50 cells built in the browser, given to the viewer as a model or written to `.xlsx` in a Web Worker and read back.
- **Performance:** time from source to `onLoad` and to the first painted frame, per run.
- **Code:** the `<XlsxViewer>` snippet for the current props, the theme CSS and the worker file when needed, and the install command for npm, pnpm, yarn or bun.
- Shareable links (settings live in the query string), a history of recent runs (localStorage), light/dark theme, keyboard shortcuts (press `?`), and the known issues of the current version.

The library is installed from npm at an exact version (`package.json`), never linked from the library repository, so the playground shows what users get.

## Local development

Node 22, 24 or 26.

```sh
npm ci
npm run dev        # http://localhost:5173
npm run typecheck
npm run lint
npm test
npm run build      # dist/
npm run preview    # serves dist/ with the same security headers as production (vercel.json)
```

## Deploying

The site is a static Vite build. On Vercel, import the repository with the framework preset **Vite** and the default build command and output directory. `vercel.json` only adds the security headers (Content-Security-Policy, `X-Content-Type-Options`, `Referrer-Policy`, frame protection); `vite preview` serves the same headers, so they are exercised locally.

To move to a new library version, change the exact `react-xlsx-viewer` version in `package.json`, run `npm install`, and update the known-issues note in `src/components/KnownIssues.tsx`.
